# TheFighter (더 파이터)

성장형 복싱 게임 「더 파이터」 프로토타입 (Godot 4).

캡슐 메쉬로 만든 두 파이터가 원형 링 안에서 겨루는 최소 기능 버전입니다.
실제 캐릭터 모델/애니메이션은 없고, 이동/펀치/블록/체력/라운드 타이머 같은
복싱 게임의 핵심 시스템만 동작하도록 구성했습니다. 게임의 축은 전투 자체보다
파이트머니로 능력치를 훈련시키고 커리어 단계를 밟아 올라가는 "성장"에
있습니다.

## 실행 방법

1. [Godot 4.3 이상](https://godotengine.org/download) 설치
2. Godot 실행 → "Import" → 이 폴더의 `project.godot` 선택
3. F5(또는 재생 버튼)로 실행

## 조작법

| 키 | 동작 |
| --- | --- |
| W / A / S / D | 이동 |
| J | 펀치 |
| L (누르고 있기) | 블록 (받는 데미지 80% 감소) |

화면 상단 중앙의 일시정지 아이콘을 누르면 게임이 실제로 멈추고(물리/타이머
정지) 계속하기·다시하기·나가기(+ 준비중인 설정) 메뉴가 뜹니다. 다시 누르면
재개됩니다.

상대는 간단한 AI로, 거리를 좁힌 뒤 랜덤하게 펀치/블록을 선택합니다.

키 배치는 지금은 고정이지만, 스킬이 늘어나면 (피파온라인 스타일로) 사용자가
직접 키를 재배치할 수 있는 설정 화면을 추가할 계획입니다 — 로드맵의 확장
아이디어 참고.

## 능력치 & 상대 스타일(archetype)

각 파이터는 `CharacterStats` 리소스로 파워/체력/스피드/스킬 능력치를 가지며,
전투 수치(최대체력, 이동속도, 펀치 데미지, 공격 쿨다운)는 전부 이 능력치에서
계산됩니다. 이후 커리어 진행에서 파이트머니로 이 능력치를 성장시키는 것이
"노가다"의 축이 됩니다.

상대 AI는 복서/난전형/카운터형/방어형 4종의 복싱 스타일(archetype) 중
하나로 등장하고, `AIController.gd`가 스타일별로 공격 빈도/블록 확률/접근
속도 같은 행동 파라미터를 다르게 적용합니다. 자세한 내용은 아래 "커리어
진행" 절 참고.

## 홈 화면 = 게임 로비

게임을 실행하면 전투가 아니라 **홈 화면**(`Career.tscn`)에서 시작합니다.
"내 캐릭터가 다음 경기를 준비하고 있다"는 느낌을 주는 게 목표라, 텍스트를
세로로 나열하지 않고 화면을 3개 영역으로 나눴습니다.

**중앙 (화면의 대부분)** — 실제 3D 씬(`SubViewport`, `ArenaViewportContainer`)이
화면 대부분을 차지합니다. 어두운 바닥/뒷벽/철제 기둥과 전구 불빛
(`OmniLight3D`) 하나로 월드오브탱크 차고 같은 "지하 체육관" 분위기를 냈고,
그 안에 플레이어 캡슐 캐릭터가 서 있습니다 — 실제 3D 캐릭터 모델이 들어와도
이 구조(카메라/조명/배경은 그대로, `CharacterPreview` 노드만 실제 모델로
교체)를 그대로 쓸 수 있게 만들어뒀습니다. 무대 단계가 오르면 조명 자체가
어두운 지하실 톤에서 밝은 챔피언 무대 조명으로 보간됩니다
(`Career.gd`의 `_apply_arena_lighting`) — 실제 배경 사진/씬을 쓰게 되면
이 라이팅 보간 대신(또는 함께) 단계별 배경 씬을 갈아 끼우면 됩니다. 3D
프리뷰 위에는 현재 무대 이름이 크게 표시되고, 왼쪽 아래에는 작은 정보
패널이 겹쳐서 전적 / 승급 조건(또는 랭크) / 팬 / 명성을 보여줍니다
(자세한 내용은 아래 "커리어 진행" 참고).

**상단** — 왼쪽에 게임 이름, 오른쪽에 파이트머니(금색)와 설정 아이콘(아직
설정 화면이 없어서 비활성 상태)이 작은 HUD 바로 배치되어 있습니다.

**하단** — 위에는 메뉴 아이콘 줄(**캐릭터**만 실제로 동작하고, **기록**/
**상점**은 아직 기능이 없어서 비활성 "준비중"으로만 자리를 잡아뒀습니다),
그 아래에 화면에서 가장 눈에 띄는 큰 빨간 **FIGHT** 버튼이 있습니다 — 이
버튼만은 전역 플랫 테마를 따르지 않고 그림자 + hover/press마다 색이
달라지는 전용 스타일(`Career.tscn`에 로컬로 정의된 `StyleBoxFlat`)을 씁니다.
누르면 바로 전투로 가지 않고 **경기 제의 화면**(아래 참고)으로 이동합니다.

홈 화면 자체는 최상위라 뒤로가기/홈 버튼이 없지만, **캐릭터** 메뉴나 **경기
제의** 화면으로 들어가면 좌상단에 공용 헤더(`MenuHeader.tscn`)로 "< 뒤로"/
"홈" 버튼이 항상 뜹니다 — 화면 이동은 전부 `Nav` 오토로드 싱글턴
(`scripts/Nav.gd`)이 이동 기록을 스택으로 들고 처리해서, 메뉴가 몇 단계로
깊어지든 뒤로가기가 정확히 이전 화면으로 돌아갑니다.

**캐릭터 메뉴**에서 파워/체력/스피드/스킬 각각 "훈련" 버튼으로 올릴 수 있고,
훈련 비용은 현재 수치가 높을수록 비싸집니다(`50 + 현재값 × 10` G) — 능력치를
올릴수록 다음 한 포인트가 더 비싸지는, 전형적인 "노가다" 성장 곡선입니다.
추후 이 메뉴에 액세서리/외형 커스터마이징도 추가할 예정입니다.

모든 진행 상황은 `user://career_save.json`에 자동 저장되고, 게임을 다시
켜면 `SaveManager`(오토로드 싱글턴)가 불러옵니다.

## 커리어 진행 — 경기 제의 방식

**플레이어가 상대나 무대를 직접 고르지 않습니다.** 대신 게임이 현재 커리어
상황(무대, 전적, 랭크, 명성)에 맞는 상대를 골라 "경기 제의"를 보내고,
플레이어는 그걸 수락하거나 거절합니다. 실제 격투 선수의 커리어를 올라가는
느낌을 내려는 의도입니다.

**흐름**: 홈에서 FIGHT → 경기 제의 화면(`MatchOffer.tscn`)에서 수락/거절 →
수락하면 전투(`Main.tscn`) → 결과가 링 위 두 선수 이름 아래 WIN/LOSE로
표시되고 잠시 뒤 자동으로 다음 경기 제의 화면으로 넘어갑니다. 거절하면
페널티 없이 바로 다른 상대로 다시 제의를 뽑습니다.

### 스테이지 1~6 (승수 기반 승급)

`UNDERGROUND → AMATEUR CIRCUIT → ROOKIE LEAGUE → FIGHT LEAGUE → ELITE →
WORLD SERIES` 각 무대는 **10경기 중 7승**이 목표입니다(`CareerConfig.
STAGE_FIGHTS_REQUIRED`/`STAGE_WINS_REQUIRED`). 거절한 경기는 경기 수에
들어가지 않습니다. 7승을 채우면(10경기를 다 안 써도) 다음 제의가 자동으로
**승급전**(`PROMOTION FIGHT`)이 되고, 승급전에서 이기면 다음 무대로
올라갑니다 — 지면 승급전 자격은 유지된 채로 다시 도전할 수 있습니다.
10경기를 다 쓰고도 7승을 못 채우면 그 무대를 처음부터(0/10) 다시
시작합니다.

### 스테이지 7~10 (랭크 기반 진행)

`RANKED`부터는 승수 대신 **랭크 숫자**로 진행합니다. RANKED 진입 시
랭크 30에서 시작해서, 이기면 1~3 낮아지고 지면 1 높아집니다
(`CareerConfig.RANK_*`). 랭크가 10 이하가 되면 자동으로 `TOP 10` 무대로,
1에 도달하면 `TITLE SHOT`으로 넘어가면서 다음 제의가 강제로 챔피언과의
**타이틀전**(`TITLE FIGHT`)이 됩니다. 이기면 `CHAMPIONSHIP` 무대로 승격하고
`is_champion`이 켜집니다.

챔피언이 된 뒤에도 게임이 끝나지 않도록 **타이틀 방어전** 흐름을 만들어
뒀습니다 — 계속 도전자가 제의로 들어오고, 일정 횟수(`TITLE_DEFENSES_FOR_
LEGEND`, 기본 5회) 방어에 성공하면 `is_legend` 플래그가 켜집니다(전설 등급
자체의 UI/보상은 아직 없고, 구조만 준비된 상태입니다).

### 경기 제의와 상대 생성 (`MatchGenerator.gd`)

상대는 플레이어가 고르는 게 아니라 `MatchGenerator.generate()`가 현재
`CareerData`를 보고 만듭니다:

- **난이도**: 쉬움/비슷함/매우 강함 중 하나가 확률적으로 뽑히고
  (`CareerConfig.DIFFICULTY_WEIGHTS`), 상대 능력치 배율과 보상 배율에
  반영됩니다. 기본은 "비슷한 상대"가 가장 많이 나옵니다.
- **AI 스타일(archetype)**: 복서 / 난전형 / 카운터형 / 방어형 4종
  (`CareerConfig.Archetype`) 중 무대 단계에 맞는 풀에서 뽑힙니다
  (`ARCHETYPE_POOL_BY_STAGE`) — 낮은 무대는 복서/난전형 위주로 좁고,
  올라갈수록 다양해집니다. `AIController.gd`가 이 값을 받아서 공격 빈도/
  블록 확률/접근 속도 같은 기존 파라미터를 archetype별로 다르게 적용합니다
  (카운터형은 맞은 직후 즉시 반격을 시도하는 정도의 가벼운 반응까지만 —
  진짜 상태머신 기반 고급 AI는 나중 단계입니다).
- **라이벌**: 가끔(`RIVAL_CHANCE`) 새 라이벌이 생기고, 라이벌이 있으면
  다음 제의가 그 라이벌과의 재대결(`RIVALRY`)일 확률이 높아집니다
  (`RIVAL_REMATCH_CHANCE`). 라이벌을 이기면 그 라이벌은 "격파됨"으로
  표시되고, 다음에 새 라이벌이 다시 생길 수 있습니다.
- **보상**: 파이트머니/팬/명성이 난이도와 무대에 비례해서 커집니다
  (`BASE_MONEY_REWARD`, `MONEY_PER_WIN`, `BASE_FAN_REWARD`,
  `BASE_FAME_REWARD`). 강한 상대일수록 위험하지만 보상도 큽니다.

경기 제의 화면(`MatchOffer.tscn`)은 상대 이름/전적/스타일/난이도(별점)와
보상(G/팬/명성)을 보여주고, 제의의 중요도에 따라 배지를 다르게 표시합니다:
`STANDARD FIGHT`(일반) → `MAIN EVENT`(어려운 일반 경기) → `RIVALRY`(라이벌전)
→ `PROMOTION FIGHT`(승급전) → `TITLE FIGHT`(타이틀전/방어전). **거절**을
누르면 페널티 없이 바로 다른 상대로 새 제의를 뽑습니다 — 원하는 상대가
나올 때까지 자유롭게 돌려볼 수 있습니다.

수락한 제의는 `MatchContext`(오토로드 싱글턴)에 저장되어 `Main.tscn`으로
넘어가고, `AIController.gd`가 그 정보로 실제 상대를 만듭니다. 경기가 끝나면
`CareerData.register_result()`가 승급/랭크/팬/명성을 한 번에 반영합니다.

### 왜 설정을 한곳에 모았나 (`CareerConfig.gd`)

스테이지 수, 스테이지당 필요 경기/승수, 랭크 임계값, 난이도 확률/배율,
보상 공식, 상대 스타일 풀, 라이벌 확률까지 전부 `scripts/CareerConfig.gd`
하나에 상수로 모아뒀습니다. 밸런스를 바꾸고 싶으면 이 파일의 숫자만
건드리면 되고, 다른 스크립트를 고칠 필요가 없습니다.

## 화면/UI 공통 규칙

- **테마**: `theme/GameTheme.tres`를 프로젝트 전역 테마로 등록해뒀습니다
  (`project.godot`의 `gui/theme/custom`). 버튼은 배경색이 아예 없는 완전
  플랫 스타일(`StyleBoxEmpty`)이고, hover 시 밑줄, pressed 시 빨간 밑줄 +
  빨간 텍스트로만 상태를 표시합니다. 패널(`PanelContainer`, 어두운 카드
  배경 + 얇은 테두리)과 체력바는 계속 배경이 있는 스타일을 씁니다. 전부
  이 파일 하나로 관리되니, 새 버튼/패널을 만들 때 씬마다 따로 스타일을
  입힐 필요 없이 기본 노드를 그대로 쓰면 자동 적용됩니다. 더 다듬고
  싶으면 이 파일의 색상/두께 값만 바꾸면 전체 화면에 한 번에 반영됩니다.
  단, 홈 화면의 **FIGHT** 버튼처럼 유난히 중요한 CTA 버튼은 전역 테마를
  따르지 않고 그 씬 안에 로컬 `StyleBoxFlat`을 만들어 개별적으로 강조합니다.
- **버튼 크기는 항상 내용에 맞춘다**: 플랫 버튼은 배경이 없어서, 버튼의
  실제 클릭 영역(=밑줄이 그려지는 영역)이 텍스트보다 훨씬 넓으면 밑줄이
  텍스트와 안 맞고 이상하게 늘어나 보입니다. 그래서 텍스트만 있는 버튼은
  컨테이너 안에서 `size_flags_horizontal = 0`(내용 크기만큼만 차지)으로
  두고, 의도적으로 넓어야 하는 버튼(FIGHT 같은 CTA)만 예외로 둡니다.
- **탭이 있는 메뉴 구조**: 캐릭터 메뉴처럼 하위 항목이 여러 개인 화면은,
  화면 전체를 다른 씬으로 바꾸는 대신 **왼쪽 사이드바 + 오른쪽 콘텐츠 패널**
  구조로 만듭니다 (`CharacterMenu.tscn`의 `Body`(HBoxContainer) →
  `Sidebar`/`ContentPanel` 참고). 사이드바 버튼을 누르면 오른쪽 콘텐츠만
  바뀌는 게 목표라, 지금처럼 탭이 하나뿐이어도 이 뼈대를 미리 만들어두고
  나머지 탭은 비활성 버튼("준비중")으로 자리만 잡아둡니다.

```
├── project.godot           # 프로젝트 설정 + 입력 맵 + 테마 + SaveManager/Nav 오토로드
├── theme/
│   └── GameTheme.tres       # 전역 UI 테마 (버튼/패널/체력바 스타일)

│   ├── MatchOffer.tscn       # 경기 제의 화면: VS 프리뷰, 상대 정보, 보상, 수락/거절
│   ├── CharacterMenu.tscn    # 캐릭터 메뉴: 왼쪽 탭(능력치/외형/악세사리) + 오른쪽 콘텐츠
│   ├── MenuHeader.tscn       # 모든 서브 메뉴 공용 헤더: "뒤로"/"홈" 버튼
│   ├── Main.tscn             # 아레나, 조명, 카메라, UI, 두 파이터 배치 (전투), 일시정지 메뉴
│   ├── Player.tscn           # 플레이어 파이터(파란 캡슐)
│   └── Enemy.tscn            # AI 파이터(빨간 캡슐)
└── scripts/
    ├── Fighter.gd          # 공통 로직: 이동/중력, 체력, 공격 판정, 피격 연출, KO
    ├── CharacterStats.gd   # 파워/체력/스피드/스킬 → 전투 수치 변환 (Resource)
    ├── CareerConfig.gd     # 커리어/매치메이킹 튜닝 수치 전부 (스테이지, 랭크, 보상, 난이도, AI 스타일 풀 등)
    ├── CareerData.gd       # 파이트머니/전적/무대·랭크/팬·명성/라이벌/능력치 세이브 데이터 (순수 데이터 클래스)
    ├── OpponentOffer.gd    # 경기 제의 한 건의 데이터 (상대/난이도/보상/중요도 태그)
    ├── MatchGenerator.gd   # CareerData를 보고 다음 경기 제의를 만드는 매치메이킹 로직
    ├── MatchContext.gd     # 오토로드 싱글턴: 수락한 제의를 홈 → 전투 씬으로 전달
    ├── SaveManager.gd      # 오토로드 싱글턴: user://career_save.json 저장/불러오기
    ├── Nav.gd              # 오토로드 싱글턴: 화면 이동 기록(스택) 관리, go_to/go_back/go_home/reset_to
    ├── MenuHeader.gd        # 공용 뒤로가기/홈 버튼 로직 (Nav 호출)
    ├── Career.gd            # 홈 화면: 정보 패널, 아레나 라이팅 보간, 서브 메뉴/경기 제의 진입
    ├── MatchOffer.gd        # 경기 제의 생성/표시, 수락 시 MatchContext 저장, 거절 시 페널티 없이 재추첨
    ├── CharacterMenu.gd     # 캐릭터 메뉴: 사이드바 능력치 탭 콘텐츠
    ├── PlayerController.gd # 키 입력 처리 + SaveManager의 능력치를 그대로 사용
    ├── AIController.gd     # MatchContext의 제의로 상대 능력치/스타일 구성, archetype별 행동 튜닝
    └── Main.gd             # 카메라 추적, HUD, 라운드 진행, 일시정지, 결과 WIN/LOSE 표시 → CareerData.register_result
```

`Fighter.gd`가 `class_name Fighter`로 선언된 베이스 클래스이고,
`PlayerController.gd`/`AIController.gd`는 이를 상속해서 "언제 움직이고 공격할지"만
결정합니다. 데미지 계산, 블록, 스태거, KO 연출은 전부 베이스 클래스에 있습니다.

`CareerData`는 일부러 Godot `Resource`가 아니라 순수 데이터 클래스로 만들어서
JSON으로 직접 저장합니다 — 커스텀 리소스 타입을 씬 파일에 직접 박아넣었을 때
겪었던 클래스 인식 문제를 피하기 위한 선택입니다.

**주의**: `Control` 씬에서 화면 전체를 덮는 `CenterContainer`/`Background` 같은
노드가 `MenuHeader`보다 트리 순서상 나중(=화면상 위)에 있으면, 그 투명한
영역이 클릭을 가로채서 `MenuHeader`의 뒤로가기/홈 버튼이 안 눌리는 문제가
생긴다 (`CharacterMenu.tscn`에서 실제로 겪은 버그). 그래서 화면 전체를 덮는
레이아웃용 컨테이너는 `mouse_filter = 2`(Ignore)로 두고, `MenuHeader`는
루트의 마지막 자식으로 둔다 — 새 메뉴를 만들 때도 이 두 가지를 지킬 것.

**새 메뉴를 추가할 때의 규칙**: 홈(`Career.tscn`)을 제외한 모든 메뉴 화면은
`MenuHeader.tscn`을 인스턴스로 넣어서 "뒤로"/"홈" 버튼을 항상 보여줘야 하고,
화면 전환은 `get_tree().change_scene_to_file()`을 직접 부르지 말고 반드시
`Nav.go_to("res://scenes/새메뉴.tscn")`을 통해서 해야 뒤로가기 기록이 정확히
쌓입니다.

## 확장 아이디어 (백로그)

- **키 재배치 설정 화면** — 스킬이 늘어나면 지금의 고정 WASD+J/L 대신, 피파온라인처럼
  사용자가 직접 키를 커스터마이징할 수 있게 (Godot의 InputMap을 런타임에
  변경하고 설정을 저장하는 방식으로 구현 예정)
- **VS 소개 화면 심화** — `MatchOffer.tscn`으로 기본적인 VS 연출(양 선수
  프리뷰, 전적/스타일/난이도, 등장 애니메이션)은 만들었습니다. 나이/몸무게/
  국가 같은 세부 프로필이나 실제 캐릭터 모델이 들어오면 더 실제 복싱 중계
  화면처럼 다듬을 수 있습니다.
- **여러 캐릭터 보유 & 구매** — 지금은 파이터가 하나뿐이고 능력치만 훈련으로
  키우는 구조인데, 파이트머니(또는 별도 재화)로 더 좋은 등급의 캐릭터를
  구매해서 로스터를 늘리고 그중 하나를 골라 경기에 내보내는 방향도 고려 중.
  다만 이건 "능력치 하나를 꾸준히 키운다"는 지금의 성장 구조와 방향이
  겹치거나 충돌할 수 있어서, 실제로 넣을 때는 (a) 캐릭터별로 완전히 다른
  베이스 스탯/스타일을 가진 카드처럼 갈지, (b) 지금처럼 하나의 파이터를
  계속 키우되 스킨/스타일 슬롯만 여러 개 살 수 있게 할지 방향을 먼저
  정해야 한다. 무대별 배경(위 항목)과도 자연스럽게 엮일 수 있는 아이디어.
- 캡슐 메쉬를 실제 3D 캐릭터 모델 + AnimationPlayer/AnimationTree로 교체
- 히트박스를 거리 기반이 아닌 `Area3D` 충돌로 정교화, 잽/훅/어퍼컷 콤보 추가
- 링 로프 메쉬, 관중석, 사운드/이펙트 추가
- 라운드제(3라운드, 판정), 체력 외 스태미나 시스템
- 멀티플레이어(로컬 2P 또는 네트워크)로 확장
