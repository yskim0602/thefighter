# TheFighter

3D MMA 격투 게임 프로토타입 (Godot 4).

캡슐 메쉬로 만든 두 파이터가 원형 케이지 안에서 겨루는 최소 기능 버전입니다.
실제 캐릭터 모델/애니메이션은 없고, 이동/타격/블록/체력/라운드 타이머 같은
격투 게임의 핵심 시스템만 동작하도록 구성했습니다.

## 실행 방법

1. [Godot 4.3 이상](https://godotengine.org/download) 설치
2. Godot 실행 → "Import" → 이 폴더의 `project.godot` 선택
3. F5(또는 재생 버튼)로 실행

## 조작법

| 키 | 동작 |
| --- | --- |
| W / A / S / D | 이동 |
| J | 펀치 |
| K | 킥 (데미지 ↑, 쿨다운 ↑) |
| L (누르고 있기) | 블록 (받는 데미지 80% 감소) |
| R | 라운드 종료 후 재대결 |
| M | 라운드 종료 후 커리어 화면으로 돌아가기 |

상대는 간단한 AI로, 거리를 좁힌 뒤 랜덤하게 펀치/킥/블록을 선택합니다.

키 배치는 지금은 고정이지만, 스킬이 늘어나면 (피파온라인 스타일로) 사용자가
직접 키를 재배치할 수 있는 설정 화면을 추가할 계획입니다 — 로드맵의 확장
아이디어 참고.

## 능력치 & 스타일 상성

각 파이터는 `CharacterStats` 리소스로 파워/체력/스피드/스킬 능력치를 가지며,
전투 수치(최대체력, 이동속도, 데미지, 공격 쿨다운)는 전부 이 능력치에서 계산됩니다.
이후 커리어 진행에서 파이트머니로 이 능력치를 성장시키는 것이 "노가다"의 축이 됩니다.

또한 각 파이터는 5가지 스타일(복싱/무에타이/레슬링/유도/주짓수) 중 하나를 가지고,
실제 UFC의 "먹이사슬"을 단순화한 3항 순환 상성이 있습니다.

```
타격가(복싱·무에타이) → 이긴다 → 그라운드 그래플러(주짓수)
그라운드 그래플러(주짓수) → 이긴다 → 테이크다운 그래플러(레슬링·유도)
테이크다운 그래플러(레슬링·유도) → 이긴다 → 타격가(복싱·무에타이)
```

상성에서 유리하면 데미지 1.25배, 불리하면 0.85배를 받습니다
(`scripts/FightingStyle.gd`). 기본 상대(지하 레슬러)는 레슬링 스타일이라
복싱 플레이어에게 유리한 상성으로 시작하도록 설계했습니다 — "지하실에서 고생하며
성장한다"는 컨셉대로, 첫 상대부터 쉽지 않게.

## 커리어 (파이트머니 · 성장 · 저장)

게임을 실행하면 전투가 아니라 **홈 화면**(`Career.tscn`)에서 시작합니다.
브롤스타즈 홈 화면처럼 위쪽엔 캐릭터를 3D로 직접 보여주는 미리보기 영역,
아래쪽엔 재화/훈련/경기 시작 UI를 배치했습니다.

- 위쪽 미리보기는 실제 3D 씬(`SubViewport`)입니다 — 어두운 바닥/뒷벽과
  전구 불빛(`OmniLight3D`) 하나로 월드오브탱크 차고 같은 "지하실" 분위기를
  냈고, 그 안에 플레이어 캡슐 캐릭터가 서 있습니다. 지금은 등급이 오르면
  배경 색상만 바뀌는데(`Career.gd`의 `TIER_BG_COLORS`), 나중에 실제 배경
  사진/텍스처를 쓰게 되면 `Background`를 `ColorRect`에서 `TextureRect`로
  바꾸고 같은 테이블을 텍스처로 교체하면 됩니다.
- 파이트머니(우측 상단, 금색), 전적(승/패), 등급(지하 파이트 → 아마추어 →
  UFC 도전자 → UFC 챔피언 — 승수 기준으로 자동 승급)을 보여줍니다.
- 아래쪽 버튼: **캐릭터**(옷걸이 아이콘)를 누르면 능력치 훈련 화면
  (`CharacterMenu.tscn`)으로 이동하고, **경기 시작**을 누르면 전투로 갑니다.
  홈 화면 자체는 최상위라 뒤로가기/홈 버튼이 없지만, 그 아래 모든 서브
  메뉴(캐릭터 메뉴 등)는 좌상단에 공용 헤더(`MenuHeader.tscn`)로
  "< 뒤로"/"홈" 버튼을 항상 보여줍니다 — 화면 이동은 전부 `Nav` 오토로드
  싱글턴(`scripts/Nav.gd`)이 이동 기록을 스택으로 들고 처리해서, 메뉴가
  몇 단계로 깊어지든 뒤로가기가 정확히 이전 화면으로 돌아갑니다.
- **캐릭터 메뉴**에서 파워/체력/스피드/스킬 각각 "훈련" 버튼으로 올릴 수
  있고, 훈련 비용은 현재 수치가 높을수록 비싸집니다(`50 + 현재값 × 10` G)
  — 능력치를 올릴수록 다음 한 포인트가 더 비싸지는, 전형적인 "노가다"
  성장 곡선입니다. 추후 이 메뉴에 액세서리/외형 커스터마이징도 추가할
  예정입니다.
- "경기 시작"을 누르면 `Main.tscn`(전투)으로 이동하고, 경기가 끝나면 보상으로
  파이트머니가 들어오고 전적/등급이 갱신됩니다 (승리 `100 + 승수×10` G,
  패배 `20` G의 위로금). 상대(지하 레슬러)도 플레이어의 승수에 따라 아주
  조금씩 강해져서, 계속 훈련해야 하는 이유가 유지됩니다.
- 모든 진행 상황은 `user://career_save.json`에 자동 저장되고, 게임을 다시
  켜면 `SaveManager`(오토로드 싱글턴)가 불러옵니다.

## 화면/UI 공통 규칙

- **테마**: `theme/GameTheme.tres`를 프로젝트 전역 테마로 등록해뒀습니다
  (`project.godot`의 `gui/theme/custom`). 버튼(둥근 모서리, hover/pressed
  색), 패널(`PanelContainer`, 어두운 카드 배경 + 얇은 테두리), 체력바까지
  이 파일 하나로 전부 관리됩니다. 새 버튼/패널을 만들 때 씬마다 따로
  스타일을 입힐 필요 없이 기본 노드를 그대로 쓰면 이 테마가 자동 적용됩니다.
  더 다듬고 싶으면 이 파일의 `StyleBoxFlat` 색상/둥근 정도만 바꾸면 전체
  화면에 한 번에 반영됩니다.
- **탭이 있는 메뉴 구조**: 캐릭터 메뉴처럼 하위 항목이 여러 개인 화면은,
  화면 전체를 다른 씬으로 바꾸는 대신 **왼쪽 사이드바 + 오른쪽 콘텐츠 패널**
  구조로 만듭니다 (`CharacterMenu.tscn`의 `Body`(HBoxContainer) →
  `Sidebar`/`ContentPanel` 참고). 사이드바 버튼을 누르면 오른쪽 콘텐츠만
  바뀌는 게 목표라, 지금처럼 탭이 하나뿐이어도 이 뼈대를 미리 만들어두고
  나머지 탭은 비활성 버튼("준비중")으로 자리만 잡아둡니다.

## 프로젝트 구조

```
thefighter/
├── project.godot           # 프로젝트 설정 + 입력 맵 + 테마 + SaveManager/Nav 오토로드
├── theme/
│   └── GameTheme.tres       # 전역 UI 테마 (버튼/패널/체력바 스타일)
├── images/
│   └── hanger_icon.svg      # "캐릭터" 메뉴 버튼 아이콘
├── scenes/
│   ├── Career.tscn          # 홈 화면: 3D 캐릭터 미리보기, 파이트머니/전적/등급, 메뉴
│   ├── CharacterMenu.tscn    # 캐릭터 메뉴: 왼쪽 탭(능력치/외형/악세사리) + 오른쪽 콘텐츠
│   ├── MenuHeader.tscn       # 모든 서브 메뉴 공용 헤더: "뒤로"/"홈" 버튼
│   ├── Main.tscn             # 아레나, 조명, 카메라, UI, 두 파이터 배치 (전투)
│   ├── Player.tscn           # 플레이어 파이터(파란 캡슐, 복싱)
│   └── Enemy.tscn            # AI 파이터(빨간 캡슐, 레슬링)
└── scripts/
    ├── Fighter.gd          # 공통 로직: 이동/중력, 체력, 공격 판정, 피격 연출, KO
    ├── CharacterStats.gd   # 파워/체력/스피드/스킬 → 전투 수치 변환 (Resource)
    ├── FightingStyle.gd    # 5가지 스타일 enum + 상성 배율 계산 (static)
    ├── CareerData.gd       # 파이트머니/전적/등급/능력치 세이브 데이터 (순수 데이터 클래스)
    ├── SaveManager.gd      # 오토로드 싱글턴: user://career_save.json 저장/불러오기
    ├── Nav.gd              # 오토로드 싱글턴: 화면 이동 기록(스택) 관리, go_to/go_back/go_home
    ├── MenuHeader.gd        # 공용 뒤로가기/홈 버튼 로직 (Nav 호출)
    ├── Career.gd            # 홈 화면: 정보 표시, 서브 메뉴/경기 진입
    ├── CharacterMenu.gd     # 캐릭터 메뉴: 사이드바 능력치 탭 콘텐츠
    ├── PlayerController.gd # 키 입력 처리 + SaveManager의 능력치를 그대로 사용
    ├── AIController.gd     # 접근 → 공격/블록을 선택하는 단순 AI (승수에 따라 소폭 강해짐)
    └── Main.gd             # 카메라 추적, HUD, 라운드 진행, 결과 → 커리어 반영/저장
```

`Fighter.gd`가 `class_name Fighter`로 선언된 베이스 클래스이고,
`PlayerController.gd`/`AIController.gd`는 이를 상속해서 "언제 움직이고 공격할지"만
결정합니다. 데미지 계산, 블록, 스태거, KO 연출은 전부 베이스 클래스에 있습니다.

`CareerData`는 일부러 Godot `Resource`가 아니라 순수 데이터 클래스로 만들어서
JSON으로 직접 저장합니다 — 커스텀 리소스 타입을 씬 파일에 직접 박아넣었을 때
겪었던 클래스 인식 문제를 피하기 위한 선택입니다.

**주의**: `Control` 씬에서 화면 전체를 덮는 `CenterContainer`/`Background` 같은
노드가 `MenuHeader`보다 트리 순서상 나중(=화면상 위)에 있으면, 그 투명한
영역이 클릭을 가로채서 `MenuHeader`의 뒤로가기/홈 버튼이 안 눌리는 문제가
생긴다 (`CharacterMenu.tscn`에서 실제로 겪은 버그). 그래서 화면 전체를 덮는
레이아웃용 컨테이너는 `mouse_filter = 2`(Ignore)로 두고, `MenuHeader`는
루트의 마지막 자식으로 둔다 — 새 메뉴를 만들 때도 이 두 가지를 지킬 것.

**새 메뉴를 추가할 때의 규칙**: 홈(`Career.tscn`)을 제외한 모든 메뉴 화면은
`MenuHeader.tscn`을 인스턴스로 넣어서 "뒤로"/"홈" 버튼을 항상 보여줘야 하고,
화면 전환은 `get_tree().change_scene_to_file()`을 직접 부르지 말고 반드시
`Nav.go_to("res://scenes/새메뉴.tscn")`을 통해서 해야 뒤로가기 기록이 정확히
쌓입니다.

## 로드맵

- [x] 1단계 — 능력치 시스템 + 스타일 상성을 전투에 연결
- [x] 2단계 — 파이트머니, 커리어 단계(지하 → 아마추어 → UFC → 챔피언), 승/패 기록,
      훈련으로 능력치 성장, 저장/불러오기 (현재)
- [ ] 3단계 — 단계별 퀘스트/승급 조건, 상대 난이도 커브(노가다 구간 설계),
      여러 상대(로스터) 추가
- [ ] 4단계 — 캐릭터 외형 커스터마이징, 타격 임팩트 이펙트, 그래플링 스킬 발동 시
      캔 애니메이션
- [ ] 5단계 — 5개 스타일 전부의 세부 스킬트리, 정교한 상성 매트릭스

## 확장 아이디어 (백로그)

- **키 재배치 설정 화면** — 스킬이 늘어나면 지금의 고정 WASD+JKL 대신, 피파온라인처럼
  사용자가 직접 키를 커스터마이징할 수 있게 (Godot의 InputMap을 런타임에
  변경하고 설정을 저장하는 방식으로 구현 예정)
- **경기 시작 전 VS 소개 화면** — UFC 중계처럼 양 선수의 이름/나이/몸무게/전적/국가/
  스타일을 나란히 보여주고 "VS"로 대결 구도를 연출하는 인트로 (Career → Main
  전환 사이에 넣을 예정)
- **여러 캐릭터 보유 & 구매** — 지금은 파이터가 하나뿐이고 능력치만 훈련으로
  키우는 구조인데, 파이트머니(또는 별도 재화)로 더 좋은 등급의 캐릭터를
  구매해서 로스터를 늘리고 그중 하나를 골라 경기에 내보내는 방향도 고려 중.
  다만 이건 "능력치 하나를 꾸준히 키운다"는 지금의 성장 구조와 방향이
  겹치거나 충돌할 수 있어서, 실제로 넣을 때는 (a) 캐릭터별로 완전히 다른
  베이스 스탯/스타일을 가진 카드처럼 갈지, (b) 지금처럼 하나의 파이터를
  계속 키우되 스킨/스타일 슬롯만 여러 개 살 수 있게 할지 방향을 먼저
  정해야 한다. 등급별 배경(위 항목)과도 자연스럽게 엮일 수 있는 아이디어.
- 캡슐 메쉬를 실제 3D 캐릭터 모델 + AnimationPlayer/AnimationTree로 교체
- 히트박스를 거리 기반이 아닌 `Area3D` 충돌로 정교화, 콤보/그래플 추가
- 케이지 펜스 메쉬, 관중석, 사운드/이펙트 추가
- 라운드제(3라운드, 판정), 체력 외 스태미나 시스템
- 멀티플레이어(로컬 2P 또는 네트워크)로 확장
